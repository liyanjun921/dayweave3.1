序时 DAYWEAVE V3.2｜零基础 Netlify 部署图解（无需 Supabase）

这份教程专门针对你看到的 The deploy directory public does not exist 报错重写。你可以一直沿用现在的 Netlify 站点，也可以新建一个。不需要安装 Node.js，不需要终端。

你最终会拥有

  • 一个 https://你的名字.netlify.app 网页地址，支持在 iPhone Safari 使用并添加到主屏幕。
  • 站长首次初始化、邮箱密码登录、管理员生成一次性邀请码、朋友凭邀请码注册。
  • 你和朋友的聊天、任务、记忆手账默认留在各自当前设备。登录相同账号不会自动跨设备同步记忆。
  • 用户以后可选独立 Supabase 备份，占用他们自己的额度；现在完全不用配置。

重要边界： 注册码和账号使用 Netlify Functions + Blobs。Blobs 不是事务数据库；同时抢同一邀请码的极端情况不保证严格一次性。本版无邮件验证码、密码找回、防暴力尝试等正式安全机制，仅供受邀亲友测试；还没有在你的真实 Netlify 账号上验证部署。

第 0 步：只准备两个网站账号

  1. GitHub：https://github.com/ — 存代码。
  2. Netlify：https://app.netlify.com/ — 发布网站、运行邀请码后端。

不要创建 Supabase 项目。 下载本安装包后先解压（Windows：右键 ZIP →「全部解压」）。

第 1 步：确认解压结构（最重要）

打开解压目录，最外层应直接看到：

📁 public
    ├── index.html          ← 网站入口，必须在这里
    ├── app.js
    ├── cloud.js
    └── ...
📁 netlify
    ├── functions
    │   ├── health.js       ← 上线体检
    │   ├── setup.js        ← 站长初始化
    │   ├── register.js     ← 邀请注册
    │   ├── login.js
    │   └── ...
    └── lib
📁 docs
📁 tests
📄 netlify.toml            ← Netlify 部署配置
📄 package.json
📄 README.md
📄 00_从这里开始_部署指南.md
📄 .nvmrc

❌ 错误：GitHub 根目录只有 dayweave-v3/ 一个文件夹，要点进去才能看到 public。

❌ 错误：GitHub 只有 ZIP 文件或「直接试玩.html」。这不会部署账号和邀请码。

✅ 正确：GitHub 仓库首页直接显示 public/ 和 netlify.toml（无需再进入别的文件夹）。

第 2 步：把解压后的内容上传到 GitHub

  1. 打开 https://github.com/new，取一个名字（例如 dayweave-v3），选 Private，点 Create repository。
  2. 进入仓库，点击 Add file → Upload files（空仓库也可以点 uploading an existing file）。
  3. 回到 Windows 文件资源管理器，进入解压出来的文件夹里面。按 Ctrl + A 选中里面的全部文件/文件夹，再一起拖进 GitHub 上传区。
  4. 等待文件列表出现，往下点击 Commit changes。
  5. 回到仓库首页核对：顶层必须直接有 public、netlify、netlify.toml、package.json。
  6. 点进 public：必须看见 index.html。

⚠️ 不要把「整个解压后的外层文件夹」拖上去，而是打开文件夹后选中里面的内容拖上去。Windows 的 Ctrl+A 如果选中了 .nvmrc 也没有问题。

如果 GitHub 上传界面不接受文件夹拖拽： 推荐使用浏览器 Chrome/Edge，或者使用 GitHub Desktop（不需要 Node.js）。暂时不要只上传几个 HTML 试图代替完整工程。

第 3 步：先生成两个口令（不用编程）

在本机双击打开 docs/SETUP_SECRET_生成加密口令.html。

它有两个按钮，分别生成：

变量名 复制哪个值？ 用途
DAYWEAVE_SERVER_SECRET ① 服务器加密密钥 登录会话签名、加密每人 AI Key
DAYWEAVE_SETUP_CODE ② 初始化口令 只用于首次创建站长

这两个值不要相同。不要截图发给别人，不要写进 GitHub。 把①存在安全的密码管理器中，将来更换①会使旧登录会话及加密存储的 API Key 失效。

另一个变量 ALLOWED_AI_HOSTS 填 AI 服务商的 主机名。例如使用 OpenAI 兼容 API，可以先填 api.openai.com。如果你用第三方中转，把它替换成第三方中转地址的域名，不带 https://、斜杠、路径。多个域名用英文逗号隔开。这个只是允许调用的主机列表，不是 API Key。

第 4 步：Netlify 连接 GitHub

  1. 打开 https://app.netlify.com/ 登录。
  2. 点击 Add new project / Add new site → Import an existing project → GitHub。不同版本菜单名字可能略有差别。
  3. 首次使用按提示授权 GitHub，选择刚才的 dayweave-v3 仓库。
  4. 如果页面有 Deploy settings / Build settings，按下表核对：
页面字段 应该是什么
Base directory 留空（非常重要）
Build command 留空，不需要手动 npm run build
Publish directory public
Functions directory netlify/functions，已经写进 netlify.toml
Branch main（或你的默认分支）

netlify.toml 已声明 publish = "public"。Netlify 会在云端安装需要的 @netlify/blobs 依赖，不需要你本地安装 Node.js。

如果你用了原来的站点，进入 Project configuration / Site configuration → Build & deploy → Build settings，把 Base directory 清空、Publish directory 改成 public。如果 GitHub 的文件其实套了外层文件夹，只改 Publish 为 public 是不够的，仍然需要处理第 2 步的目录结构。

第 5 步：给 Netlify 配环境变量

在 Netlify 当前项目里找到 Project configuration / Site configuration → Environment variables → Add a variable。

依次添加 3 个变量（复制第 3 步生成的值）：

DAYWEAVE_SERVER_SECRET = ①服务器加密密钥
DAYWEAVE_SETUP_CODE    = ②站长初始化口令
ALLOWED_AI_HOSTS       = api.openai.com

确保变量对 Functions 运行环境可用（通常选择 All scopes 最省心），然后保存。

不要把 SUPABASE_URL、SUPABASE_SERVICE_ROLE_KEY、APP_ENCRYPTION_KEY 填到这一版中；这些是旧版教程或其他方案使用的字段。

若已经部署过，需要在 Deploys 中触发 Trigger deploy → Deploy site / Clear cache and deploy（菜单文案会略有差别）。

第 6 步：验证网站和后端

等 Netlify 部署显示 Published / Production，点击 Netlify 提供的站点 URL。

① 检查首页：应该看到序时玻璃手账 UI。

② 检查邀请码后端（新增）：把下面这段加在你的网站域名后面，放到浏览器地址栏：

/.netlify/functions/health

假设你的站点是 https://hello-dayweave.netlify.app，那么检查网址为：

https://hello-dayweave.netlify.app/.netlify/functions/health

健康时应返回类似：

{"app":"DAYWEAVE","ok":true,"functions":"available","serverSecret":"configured","storage":"available"}
  • 如果显示 "ok":false、serverSecret: missing_or_invalid：检查 DAYWEAVE_SERVER_SECRET 的名称和 Base64 内容。
  • 如果 storage: unavailable：看 Netlify 的 Functions 日志，检查 @netlify/blobs 和站点环境。
  • 如果 404：Functions 没有成功部署；可能上传文件缺失或 Functions 配置有问题。
  • 如果首页 Page not found 或 public does not exist：回头检查第 1、2、4 步。

第 7 步：第一次创建站长账号

  1. 用 Netlify 的 HTTPS 网址打开首页。
  2. 点右上角 「登录 / 邀请注册」。
  3. 输入你的邮箱地址以及不少于 10 位的密码。
  4. 点击 「我是站长 · 首次初始化」。
  5. 在展开的口令输入框里粘贴第 3 步的 ② DAYWEAVE_SETUP_CODE。
  6. 点击 「创建站长账号」；成功后应该显示自己的账号名称。
  7. 成功初始化后，回到 Netlify 环境变量，删除 DAYWEAVE_SETUP_CODE 并重新部署一次。这不会删除站长账号。

密码务必妥善保存：当前简化版没有忘记密码找回功能。

第 8 步：生成邀请码，邀请一位朋友测试

  1. 站长登录后，打开 「登录 / 邀请注册」 窗口。
  2. 找到 「管理员 · 邀请码」 → 「生成一个一次性邀请码」。
  3. 复制 DW-... 开头的邀请码，和你的 Netlify 网址一起发给朋友。
  4. 朋友填写自己的邮箱、密码、邀请码，点击 「使用邀请码注册」。
  5. 成功后自动登录。再用另一位测试账号试相同邀请码，应被拒绝。普通朋友也不应该看到管理员生码按钮。

邀请几十位朋友时请做到每人单独生成一个码，不要公开晒码；这版不适合陌生人大规模注册，邀请码的并发一次性约束并非数据库级保证。

第 9 步：怎么在 iPhone 上使用？

  • 用 iPhone Safari 打开 Netlify 的 HTTPS 网站。
  • 点分享按钮，选择 添加到主屏幕，会出现序时图标。
  • 每位用户先做一份导出备份：记忆默认保存在当前设备浏览器，不是存到 Netlify 站点。清理浏览器数据、换设备可能丢失记忆。
  • 番茄钟、打开页面时的随机主动来信可以体验，但关掉网页后可靠推送尚未实现。

第 10 步：五个最常见报错

A. The deploy directory public does not exist

Netlify 找不到 public 文件夹。 去 GitHub 仓库首页确认有 public/。如果要先点进某个外层目录才能看见 public，说明放错层级了。

修法一（推荐）：把解压目录中的所有内容直接上传到仓库顶层，保持完整文件夹。然后重新部署。

修法二（已经上传了外层文件夹、不想移动）：把 Netlify Base directory 指向真正装有 netlify.toml 和 public/ 的那个目录，例如 dayweave-v3-netlify-only，Publish directory 仍是 public。只能填仓库里真实存在的目录，不能猜。

B. Page not found / 白屏

看 Netlify Build log 有没有 Published；确认 GitHub 的 public/index.html 存在，以及 Publish 目录为 public。如果 HTML 能打开但白屏，打开浏览器控制台检查 JS 加载错误。

C. 有网站，但是登录提示请求失败 / 404

先访问 /.netlify/functions/health。如果它 404，说明你可能只上传了 HTML，没有上传 netlify/functions，或静态文件发布了而 Function 构建失败。

D. 「站长初始化口令不正确」

必须输入第二个生成的口令（DAYWEAVE_SETUP_CODE），不是服务器加密密钥，也不是自己的 AI Key。修改 Netlify 环境变量后要重新部署。

E. AI 连不上

先确认登录正常，然后检查自己的 API 地址、模型名、Key；再确认主机在 ALLOWED_AI_HOSTS。本产品当前按 OpenAI 兼容 Chat Completions 接口请求；并非所有语音/多模态模型都直接兼容。

最后，对发布版本的真实边界

  • 代码层测试通过 ≠ 你的 Netlify 线上部署已通过。首次上线务必使用测试邀请码进行验收。
  • 账号、邀请码与各自加密的模型 Key 存 Netlify Blobs；聊天、记忆手账、任务默认只留本机。
  • GitHub 仓库选 Private 可减少源码曝光，但部署出去的前端 HTML/JS 本来就能被浏览器访问；绝不要在仓库或 public 里放秘密。
  • 本版无邮箱归属验证、密码找回、完善限流和原子邀请码兑换，先用于受邀亲友。需要面向几十人持续正式运营，建议再提升认证和数据库事务能力。
  • 若你以后要用个人 Supabase 云盘，请再看 docs/用户自选Supabase云盘教程.md，部署邀请制本身不需要它。
